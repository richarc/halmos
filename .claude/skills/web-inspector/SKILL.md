# Safari Web Inspector

- `wails3 task run DEV=true` — the build to use whenever **Safari's Web Inspector** is needed (profiling, console, network tab). The default `build` and `run` pass `-tags production`, under which Wails compiles its devtools out and `inspector_darwin.go` is excluded, so the app is absent from Safari's Develop menu however long you look. Two things have to be true for Safari to list it and attach: the WKWebView's `inspectable` property and WebKit's `developerExtrasEnabled` preference. `inspector_darwin.go` sets both from a `WindowDidBecomeKey` hook. Wails beta.30's dev build sets only `inspectable` on macOS 13.3+ (beta.12 set only `developerExtrasEnabled`); without our hook a beta.30 dev build is listed but will not attach (seen 2026-10-17). The `private_mac_apis` tag does not change this on 13.3+. The first dev build recompiles every cgo object and takes ~20 minutes; after that the Go cache makes it seconds. `strings "bin/Halmos Editor" | grep -c hermesSetInspectable` is 1 for a dev build and 0 for production; it shows the hook is compiled in, not that it ran. The render pipeline carries User Timing measures (`lib/perf.ts`: `hermes:render`, `hermes:preview-dom`, `hermes:hydrate-*`) — read them with `performance.getEntriesByName('hermes:render')` in the Console, since a Timeline export keeps the marks but drops the measures.
