# Safari Web Inspector

- `wails3 task run DEV=true EXTRA_TAGS=private_mac_apis` — the build to use whenever **Safari's Web Inspector** is needed (profiling, console, network tab). The default `build` and `run` pass `-tags production`, under which Wails compiles its devtools out and `inspector_darwin.go` is excluded, so the app is absent from Safari's Develop menu however long you look. Two things have to be true for Safari to list it and attach: the WKWebView's `inspectable` property (Wails' dev build sets it since beta.30, and `inspector_darwin.go` also sets it from a `WindowDidBecomeKey` hook) and WebKit's `developerExtrasEnabled`, which since beta.19 Wails sets only under the `private_mac_apis` build tag. Without the tag the app is listed in the Develop menu but the inspector will not attach (checked on beta.30, 2026-10-17). `EXTRA_TAGS` is passed through to the dev build only; never add that tag to production builds. The first dev build recompiles every cgo object and takes ~20 minutes; after that the Go cache makes it seconds. `strings "bin/Halmos Editor" | grep -c developerExtrasEnabled` is 1 for a dev build with the tag and 0 otherwise. The render pipeline carries User Timing measures (`lib/perf.ts`: `hermes:render`, `hermes:preview-dom`, `hermes:hydrate-*`) — read them with `performance.getEntriesByName('hermes:render')` in the Console, since a Timeline export keeps the marks but drops the measures.
