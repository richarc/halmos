# Pre-1.0 clean-up: architecture review findings

Date: 2026-10-30. Source: an architecture review of the Go code and of the
app's use of Wails v3.0.0 (two independent reviewers, main claims checked
against the code). Roadmap: v1.0.0, "Pre-1.0 clean-up" (serves M1.0).

## Intent

Before the 1.0 freeze, fix the small defects the review found, bring the
Wails integration up to v3.0.0's intended patterns, and make the structural
changes that get harder after 1.0: typed events, smaller services, packages
for the parts that are already independent of Wails, and a slimmer
`App.svelte`. Nothing here changes what a user sees, except where a bug is
fixed.

## Summary of the review

The code is in good shape. `go vet` is clean, `go test -race ./.` passes
with no races, Go statement coverage is 78%. Logic is separated from I/O by
injected fields; tests use real temp folders and `httptest`. Locks are
commented. The image route, the Keychain token store and the portal
client's redirect rules are sound. All six services are registered the
standard way and every frontend call goes through generated bindings. The
custom print path, the root Taskfile's licence/Quick Look tasks and the
exact version pins are justified deviations and stay.

## Findings, by priority

### Do now

1. `RevealExport` (`portalservice.go:383`) starts `open -R` and never waits,
   leaving a finished process per use until quit. Wait for it.
2. `errMisconfigured` (`portalservice.go:59`) is one shared `*PortalError`
   returned from six places; a caller that changes it changes it for all.
   Return a new value each time.
3. `memoryStore` (`credentials.go:30`), a test double, ships in the app.
   Move it to a test file.
4. `ReadBibliography` (`documentservice.go:586`) reads any path the page
   sends. Accept only bibliography files (`.bib`, on both the name and the
   file a symlink leads to), as the image route does.
5. Print and Export PDF find their webview through `[NSApp keyWindow] ?:
   [NSApp mainWindow]` (`print_darwin.go:72`, `:157`). With a panel key or
   the app inactive this finds nothing and Print falls back to Wails'
   landscape print. Pass the app window (`NativeWindow()`), as
   `inspector_darwin.go` does.
6. `wails3 dev` is probably broken: `build/config.yml` runs `wails3 task
   run`, whose hand-added `deps: [build]` rebuilds a production binary
   without the Vite dev server. Make dev mode build a dev binary, once.

### Worth doing before 1.0

7. Settings lost update: the menu reads the settings, changes one field and
   writes the whole value back (`menu.go:126`, `:146`, `:228`). Give the
   store an atomic `update(func(*Settings))`.
8. File errors reach the UI as raw strings ("open /Users/…: permission
   denied"). Return a typed file error with a code the frontend can branch
   on, through Wails' `MarshalError`.
9. Saving a symlinked document replaces the link with a regular file, and
   every save drops extended attributes such as Finder tags
   (`atomicwrite.go`). Write through the link and keep the tags.
10. About 30 untyped events. Register them with `application.RegisterEvent`
    (structured payloads with their Go type, the rest `application.Void`)
    so the generator types them for the frontend and Wails checks them.
11. `build/darwin/Taskfile.yml` predates v3.0.0's template (fresh bundle per
    build, `xattr -cr` before signing, signature verification, a DMG task).
    Port those by hand, keeping the `deps` line; never run
    `update:build-assets`.
12. Two quit paths: ⌘Q goes through `reclaimQuitItem` and `quitRequest`,
    the Dock's Quit through `ShouldQuit`. Use one if ⌘Q with its role
    restored reaches `ShouldQuit` with the same behaviour.
13. `DemoService` stops through `Options.OnShutdown`; Wails' form is the
    service's own `ServiceShutdown`.
14. No fuzz tests. Cheap targets: `parseUpdateFeed`, `validateOrigin`,
    `localImageFile`, `parseStyleIndex`.

### Later, still before 1.0

15. `DocumentService` has about 30 fields. Move settings and the update
    check into their own services.
16. Move the parts already independent of Wails into `internal/` packages:
    file primitives, the portal client and auth, the style and tutorial
    clients.
17. `App.svelte` (2,389 lines): move event subscriptions into
    `lib/appEvents.ts` (after 10), and the disk-change and recovery-draft
    state into its own module.
18. A non-macOS build fails on the unconditional `pkg/mac` import in
    `menu.go`, and `currentPath` and `newKeychainStore` have no non-darwin
    versions. Make `GOOS=windows go vet ./.` pass and check it in CI.
19. `inspector_darwin.go`'s comments refer to beta.30; v3.0.0's dev build
    sets `inspectable` itself. Check whether Inspect Element still needs
    the file; delete it or update the comments.
20. Many comments record history ("the previous code…"). Trim them to the
    reason in the files this clean-up touches.

## Not in this clean-up

- Cancelling a Word/LaTeX export from the UI (bindings use
  `context.Background()`): export is hidden until v1.1.0; it goes with that
  work.
- `--` before the path in `open -R`: the path always comes from a save
  panel and is absolute, so it cannot read as an option.
- Go refusing writes to paths it did not hand out: `OpenPath` takes paths
  from the frontend, so this needs its own design. Backlog.
- Shutting down background goroutines at quit: they die with the process.

## Constraints

- Wails stays at exactly v3.0.0; KaTeX 0.19.1 and Mermaid 12.2.0 stay.
- Never run `wails3 task common:update:build-assets`.
- The data folder, bundle id and module keep the name `hermes`.
- Both tag sets stay green: `go test ./.` and `go test -tags nopaid ./.`.
- No change to what the user sees, except fixed bugs.
