# v0.12.0 — Seamless citations: design

Date: 2026-10-12. Source: ROADMAP.md, v0.12.0. The user skipped the design
questions and asked for the design to be written from the roadmap, so every
decision below not stated in the roadmap is marked **(my call)**.

## Intent

Citations are Hermes's main strength and stay free (ROADMAP.md, Direction).
This release removes the everyday friction of citing: finding the key,
checking what a key points to, finding broken keys before submitting,
changing style, and getting Zotero working. Footnotes ride along because
academic writing needs them and they interact with citations.

All work is local. No server, no network beyond the existing Zotero calls
to `127.0.0.1:23119`.

## Goals

1. Citation autocomplete from the document's `.bib`.
2. Formatted reference preview when hovering a citation key in the editor.
3. Unknown-key warnings in the editor, plus one place listing all of them.
4. Citation style picker, including any `.csl` file on disk.
5. Zotero insertion that tells the user exactly what is wrong when it does
   not work.
6. Footnotes in the preview and the PDF.

## Non-goals

- Anything on the server (DOI lookup, reference check, Word export — v1.1.0).
- Editing the `.bib` from Hermes.
- Note-based citation styles (citations rendered as footnotes, e.g. Chicago
  notes). Footnotes here are the author's own notes.
- Locales other than en-US. A loaded `.csl` that asks for another locale
  still formats with en-US. **(my call)**
- A Hermes-native Zotero library browser via Zotero 7's local API. See
  goal 5. **(my call)**

## Anti-goals

- Autocomplete or warnings that disagree with what the preview resolves.
  The preview's citation rule (`lib/citations.ts`) is the authority.
- Anything that rewrites a citation the user typed without being asked.
- Typing latency. Every new editor extension must stay off the keystroke
  path for large documents (Hermes had a whole release, v0.11.0, on render
  performance).

## Current state (from the code)

- Citation syntax: `citationPlugin` in `lib/citations.ts` (markdown-it
  inline rules, Pandoc subset: `[@key]`, `[see @a, p. 3; @b]`, bare `@key`).
  `KEY_RE` is the key charset.
- Formatting: `createCitationFormatter(entries, styleId)` builds a citeproc
  engine lazily and exposes `format(clusters)` and `has(key)`. Five styles
  bundled as `STYLE_IDS` (`apa`, `chicago-author-date`, `ieee`, `vancouver`,
  `harvard`); an unknown id falls back to APA with a toast.
- `App.svelte` `reloadBibliography()` reads the `.bib` through Go
  (`ReadBibliography`, path resolved against the document by
  `resolveAgainstDoc`), parses it with `parseBib` (`lib/bibliography.ts`,
  gives `CSLEntry[]`), and rebuilds `formatter`. Triggered by frontmatter
  `bibliography`/`csl` changes and by `bib:changed`.
- Preview already marks an unresolved cluster as
  `<span class="cite-error">[@key?]</span>` (`renderer.ts`).
- `lib/citationFeedback.ts` warns after a Zotero insertion that inserted
  keys are not in the `.bib`.
- Zotero: `PickCitations` (`zotero.go`) GETs Better BibTeX's CAYW endpoint;
  any failure becomes the toast "Zotero (with Better BibTeX) isn't running".
- Editor protection: `isProtected` (`lib/markdownCommands.ts`);
  spell check already finds citations by pattern (`lib/spellcheck.ts`,
  `CITATION_GROUP`, `BARE_CITATION`).
- UI surfaces: toolbar (Open, Save, Cite, Chart, Table, Export PDF), a
  status bar showing the filename, Insert and Format menus in `menu.go`.
- Frontmatter parse: `lib/frontmatter.ts`, known keys `bibliography`,
  `csl`, `toc`, `toc-depth`. No helper writes a frontmatter key yet.
- Not installed: `@codemirror/autocomplete`, a footnote plugin.

## Design

### 1. Citation autocomplete

- Trigger: typing `@` where a citation key can start — inside `[...]` after
  `[`, `;` or whitespace, or a bare `@` not preceded by a word character
  (same rule as `narrativeRule`, so an email address never triggers).
  Also on explicit request (Ctrl-Space, CodeMirror's default). Never inside
  protected ranges (`isProtected`: code, frontmatter) or maths.
- Source: the entries of the loaded bibliography. Each option shows key,
  first author's family name, year and title; matching is on key, author
  and title words. Picking inserts the key only (the `[` and `]` are the
  user's).
- No bibliography loaded: no popup, no error. **(my call)**
- Library: `@codemirror/autocomplete`, added to `Editor.svelte` with the
  completion source supplied by App (the entries live in App). Check its
  default keymap against `menu.go` accelerators and `defaultKeymap` before
  enabling (CLAUDE.md rule on accelerators).
- Toolbar Cite and Insert → Citation… keep calling Zotero.

### 2. Reference preview on hover

- Hovering a citation key in the editor shows a tooltip with the formatted
  bibliography entry in the document's current style. An unknown key shows
  "Not in <bib name>". **(my call)**
- Needs a new formatter method, `reference(key): string | null`, returning
  the bibliography HTML for one entry. It must not disturb `format()`'s
  cache or results; cache per key until the formatter is replaced.
- CodeMirror `hoverTooltip`. Locating the key under the pointer uses the
  same recogniser as goal 3.

### 3. Unknown-key warnings

- Editor: a key not in the `.bib` gets a wavy underline in the existing
  `--cite-error-fg` colour, the one the preview already uses for them. Only when a
  bibliography is loaded; a document with no `bibliography:` gets nothing.
- Status bar: "N unknown citations" appears beside the filename when N > 0.
  Clicking it opens a list of the unknown keys with their line numbers;
  clicking an entry jumps the editor there (`jumpToLine` already exists).
  **(my call)** — the status bar is the one place always on screen and
  never printed.
- Preview: unchanged (`cite-error` already marks them).
- Recognising keys in the editor: one shared recogniser in a new
  `lib/citationKeys.ts` returning `{ key, from, to }` for every key in a
  text. It must agree with `citationPlugin` on what is a citation — test it
  against the same cases as `citations.test.ts` and assert agreement with
  `extractCitationKeys` on a corpus. Decoration over visible ranges only;
  the full-document scan for the status count runs debounced, off the
  keystroke path.

### 4. Citation style picker

- Format menu gets a "Citation Style" submenu: the five bundled styles with
  a tick on the current one, a separator, then "Other Style File…".
  **(my call: Format menu, beside the existing formatting commands)**
- Choosing a bundled style writes `csl: <id>` into the frontmatter, adding
  the key if missing, creating a frontmatter block if there is none. It is
  an ordinary editor transaction, so it is undoable and marks the document
  dirty.
- "Other Style File…" opens a native open panel filtered to `.csl`, then
  writes `csl:` as a path — relative to the document when it is in the
  document's folder or below, absolute otherwise (same rule as
  `bibliographyReference`). An unsaved document cannot hold a relative
  path: the item asks the user to save first. **(my call)**
- Loading: `csl:` that is a bundled id loads as now. Any other value ending
  in `.csl` is read through Go, resolved with `resolveAgainstDoc` (new
  binding, mirroring `ReadBibliography`). Read failure or a style citeproc
  rejects: toast and fall back to APA, as unknown ids do today.
- Watch the file the way the `.bib` is watched? No: read on load and on
  frontmatter change only. **(my call)** — style files rarely change.
- The menu tick needs the current style in Go. Menu is rebuilt from Go
  state; the frontend reports the current `csl` value with a new binding
  call when it changes. Builder decides the exact mechanism.
- New Document dialog keeps its existing style select (bundled only).

### 5. Zotero without Better BibTeX

- The CAYW picker is a Better BibTeX feature, and the keys it returns must
  match the `.bib`, which in practice is a Better BibTeX export. Replacing
  it is a library browser of Hermes's own, which is v1.3.0 territory.
  **(my call)** This release makes failure explain itself instead.
- `PickCitations` distinguishes three cases and returns a typed error:
  1. Zotero not running: `GET 127.0.0.1:23119/connector/ping` fails.
  2. Zotero running, Better BibTeX missing: ping succeeds,
     `GET /better-bibtex/cayw?probe=true` does not return `ready`.
  3. Picker failed otherwise: show the error.
- Messages, shown in a dialog rather than a toast, because they carry
  steps: **(my call)**
  1. "Zotero isn't running. Open Zotero, then try again."
  2. "Zotero is running but the Better BibTeX plugin isn't installed.
     Hermes uses it to pick citations and to export your library as a
     .bib file." plus a button opening the Better BibTeX install page in
     the browser.
- Autocomplete (goal 1) is the route that needs no Zotero at all, and the
  dialog for case 2 says so.

### 6. Footnotes

- Syntax: Pandoc/markdown-it-footnote — `[^1]` references with `[^1]: text`
  definitions, and inline `^[text]`.
- Library: `markdown-it-footnote` (MIT). Add to `renderer.ts`.
- Order at the end of the document: References first, then Footnotes,
  matching Pandoc so a later Pandoc export (v1.1.0) agrees. **(my call)**
- A citation inside a footnote is formatted like any other citation.
- Footnote references and back-links are in-page `#fragment` links: they
  must scroll the preview, not go through `Preview.svelte`'s external-link
  handler. In the PDF they should be working links (the exported TOC
  already proves fragment links survive PDF export).
- Spell check: `[^label]` markers are protected. Scroll sync: the footnote
  block carries a `data-source-line` anchor like the References heading.
- Styling under the colour contract (`styleContract.test.ts`).

## Constraints

- Stack and rules in CLAUDE.md apply: bindings regenerated, never
  hand-edited; menu accelerators owned by `menu.go`; colours only as
  palette tokens with both theme blocks matching.
- Go tests with `go test ./.`; frontend tests with `npm --prefix frontend
  test`; `svelte-check` clean.
- New dependencies: `@codemirror/autocomplete`, `markdown-it-footnote`.
  Both MIT; check whether the licence bundling task needs to list them
  (it currently lists only Apache NOTICE, citeproc and CSL).
- Version stays 0.11.4 until release preparation, then 0.12.0 in every
  place the v0.11.4 release touched.

## Left to the builder

- Exact UI of the unknown-citation list (popover or small dialog).
- How the current `csl` value reaches Go for the menu tick.
- Ranking of autocomplete matches.
- Whether the hover tooltip and the underline share one ViewPlugin.
- Footnote CSS details.

## Testing

- Unit: recogniser agreement with `citationPlugin`; completion source
  filtering and the no-bibliography case; `reference(key)` not disturbing
  `format()`; frontmatter `csl:` write (no block, block without key, block
  with key, CRLF); `.csl` path resolution; footnote rendering order with
  References; Go `PickCitations` three-way error with an `httptest` server.
- Manual (user): autocomplete feel on a large `.bib`, hover tooltip,
  status-bar list jump, style menu tick, Zotero states (quit Zotero; disable
  Better BibTeX), footnote links in preview and PDF.
