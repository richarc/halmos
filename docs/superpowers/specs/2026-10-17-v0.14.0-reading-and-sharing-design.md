# v0.14.0 — Reading and sharing: design

Date: 2026-10-17. Source: ROADMAP.md, "Reading and sharing" (labelled v0.13.0
there; v0.13.0 was used by the Halmos rename, so this is v0.14.0). The user
skipped the design questions and asked for the design to be written from the
roadmap, so every decision below not stated in the roadmap is marked
**(my call)**.

## Intent

Smaller improvements for reading and sharing documents: let people see a
Halmos document without opening the app, share a draft without making a PDF,
paste figures straight in, and read for longer in comfort. They also make
Halmos easier to show to the people an author works with: co-authors,
supervisors and reviewers.

## Goals

1. Quick Look preview of `.md` files in Finder.
2. Task lists and GitHub-style alerts in the preview and PDF.
3. A copy button on code blocks in the preview.
4. Paste an image into the editor; it is saved beside the document.
5. Export to one self-contained HTML file.
6. A third theme (sepia) and a choice of body font for the document.

## Non-goals

- Editing in Quick Look, or Quick Look thumbnails (icons in Finder).
- Ticking a task-list checkbox in the preview to change the source.
  Checkboxes are read-only; the source is edited in the editor. **(my call)**
- Drag-and-drop of image files into the editor (paste only). **(my call)**
- Resizing or converting pasted images.
- HTML export that stays interactive (live charts, the outline). The export
  is a static page.
- Fonts that Halmos has to bundle. Only fonts every Mac already has.
  **(my call)**
- Themes for Mermaid and Vega-Lite beyond what light/dark already do.

## Anti-goals

- Anything that slows the editor or the preview render.
- An exported HTML file that loads anything from the network, or runs
  scripts.
- A pasted image saved somewhere the user cannot find, or overwriting an
  existing file.
- A Quick Look extension that breaks signing, notarization or the release
  task.

## Current state (from the code)

- Renderer: `lib/renderer.ts` builds HTML with markdown-it (shared setup in
  `lib/markdownParser.ts` since v0.12.0, used by the renderer, the citation
  recogniser and citation feedback). `html: false`, `linkify: true`, KaTeX,
  footnotes, citations, figures, ToC. Fences: Vega-Lite and Mermaid become
  placeholders hydrated in `Preview.svelte`; other fences are highlighted by
  `lib/codeHighlight.ts`.
- Local images: `renderer.ts` rewrites a document-relative `<img src>` to
  `/_hermes/image?doc=…&src=…`, served by `localimages.go` via
  `resolveAgainstDoc`.
- Themes: `Theme` setting is `system`/`light`/`dark` (`settings.go`, clamped
  in `normalise`); View → Appearance uses radio items; `style.css` has a
  `:root` palette and a `:root[data-theme="dark"]` block that
  `styleContract.test.ts` requires to define the same names; the dark `--bg`
  is duplicated in `main.go` (`windowBackground`), checked by
  `windowbg_test.go`.
- Document font: `--doc-font-body: ui-serif, 'New York', Georgia, serif`
  (`style.css`), used by the preview and therefore the PDF.
- Export: PDF through `print_darwin.go`. No other export.
- `.md` association since v0.11.4 (`CFBundleDocumentTypes`, extension-based).
- Clipboard: `@wailsio/runtime` exposes `Clipboard`.

## Design

### 1. Quick Look preview

The riskiest item. It starts with a spike, and the release can ship without
it if the spike fails. **(my call)**

- A Quick Look Preview Extension (`.appex`) inside
  `Halmos Editor.app/Contents/PlugIns/`, built with Swift from a small Xcode
  project or `swiftc`/`xcodebuild` call driven by the Taskfile.
- View-based (`QLPreviewingController`) hosting a `WKWebView`, which loads a
  **preview-only page** built from the same frontend: markdown-it, KaTeX,
  footnotes, figures, task lists and alerts, code highlighting, Mermaid and
  Vega-Lite charts. No editor, no bindings, no Wails runtime. The extension
  reads the file it is given and hands the text to that page.
- Citations: the extension is sandboxed and can only read the file Quick Look
  hands it, so a `.bib` beside it cannot be read. Citations show as their raw
  keys. Local images likewise do not load. Both are stated in the docs.
  **(my call)**
- Light theme always. **(my call)**
- Signing: the appex is signed with the same Developer ID, with the App
  Sandbox entitlement (required for Quick Look extensions), before the outer
  app is signed. `wails3 task release` and `bundle:licences` must sign it in
  the right order; notarization must accept it.
- The spike's question: does a view-based extension with a `WKWebView`
  running the bundled JavaScript work and pass notarization, from a Wails
  build? If not, ship without Quick Look and record why in the roadmap.

### 2. Task lists and alerts

- Task lists: `- [ ] item` / `- [x] item` render as disabled checkboxes.
- Alerts: `> [!NOTE]`, `> [!TIP]`, `> [!IMPORTANT]`, `> [!WARNING]`,
  `> [!CAUTION]` render as a titled, tinted callout.
- Plugins: `@mdit/plugin-tasklist` and `@mdit/plugin-alert` (maintained, MIT),
  added in `lib/markdownParser.ts` so the renderer and the citation
  recogniser stay in step. **(my call)** If either does not fit (e.g. it
  emits raw HTML that `html: false` blocks), a small local rule is fine.
- Styles: new palette tokens for the five alert colours, in every theme
  block (light, dark, sepia). PDF keeps the tint and avoids breaking an alert
  across pages.
- Spell check: the `[!NOTE]` marker is protected; the alert text is checked.

### 3. Copy button on code blocks

- A small "Copy" button at the top right of each highlighted code block in
  the preview, shown on hover and on keyboard focus. Not on Vega-Lite or
  Mermaid blocks (they render as charts). **(my call)**
- Copies the block's source text (not highlighted HTML) through the Wails
  `Clipboard` runtime. The button reads "Copied" for about 1.5 s.
- Hidden in print/PDF and absent from HTML export.

### 4. Paste an image

- Pasting image data (a screenshot, an image copied from another app) into
  the editor saves it and inserts `![](images/<name>.png)` at the cursor, with
  the cursor placed between `[` and `]` so the author can type a caption
  straight away (a caption is what makes a figure). **(my call)**
- Where: an `images/` folder beside the document, created on first paste.
  **(my call)**
- Name: `pasted-YYYYMMDD-HHMMSS.png` (local time), with `-2`, `-3`… added if
  the name exists. Never overwrites. **(my call)**
- Format: PNG for clipboard bitmaps; a copied JPEG/GIF/WebP file keeps its
  type. **(my call)**
- Untitled document: nothing is written; a message says "Save the document
  before pasting images". **(my call)**
- Go binding `SavePastedImage(docPath string, data []byte, ext string)
  (relPath string, err error)` writes atomically (`atomicwrite.go`) and
  returns the path relative to the document.
- Plain-text paste is unchanged. A paste with both text and an image (e.g.
  from a web page) inserts the text as now. **(my call)**

### 5. Export to HTML

- File → Export HTML… writes one `.html` file chosen in a save panel,
  defaulting to the document's name beside it.
- Content: the rendered document as the preview shows it (citations,
  References, footnotes, figures, ToC, maths, code highlighting, task lists,
  alerts), in the light theme and the chosen body font. **(my call)**
- Self-contained:
  - The stylesheet rules the document needs, inlined in `<style>`.
  - KaTeX: its CSS inlined and its fonts embedded as data URIs (only the
    fonts the page uses, if the build makes that practical; otherwise all).
  - Charts and diagrams: their rendered SVG inlined.
  - Local images: read through Go and embedded as data URIs. Remote images
    keep their URL.
- No `<script>`. Links stay links. The page has a `<title>` from the first
  heading, or the file name.
- Size: a document with many images can make a large file; no limit, but
  the docs say so.
- Go side: a save panel binding and a write binding; the frontend assembles
  the HTML (it holds the rendered DOM, including hydrated charts).

### 6. Sepia theme and body font

- Theme: `sepia` joins `system`/`light`/`dark` in the `Theme` setting and
  View → Appearance. A `:root[data-theme="sepia"]` palette block with the
  same names as the other two; `styleContract.test.ts` checks every theme
  block, not exactly two. Window background colour added to `main.go` with
  the `windowbg_test.go` check extended. Charts and diagrams use their light
  styling in sepia. **(my call)**
- Body font: a `BodyFont` setting with View → Body Font: **New York**
  (default, today's font), **Charter**, **Iowan Old Style**, **Palatino**,
  **Georgia**, **System Sans** (`-apple-system`). All ship with macOS.
  **(my call)** It sets `--doc-font-body` on the preview root, so the PDF and
  HTML export use it too. The editor font is unchanged.

## Constraints

- Rules in CLAUDE.md apply: bindings regenerated, palette tokens only,
  accelerators in `menu.go`, settings through `settings.go`'s `Settings`
  struct, render-path performance.
- New dependencies are MIT/BSD and added to the third-party licence work in
  v1.0.0.
- Version stays 0.13.0 until release preparation.
- Quick Look must not change the bundle identifier or break the existing
  signing order in `wails3 task release`.

## Left to the builder

- Exact alert colours and icons (within the palette contract).
- How the HTML export collects the stylesheet (whole sheet vs. used rules).
- Copy-button placement details.
- Whether the Quick Look extension is built by `xcodebuild` or `swiftc`.

## Testing

- Unit: task-list and alert rendering; spell-check protection of alert
  markers; copy button present on highlighted fences only and absent in
  print; paste naming, collision suffixes, untitled refusal, relative path
  (Go); HTML export contains no `<script>`, no `/_hermes/image` URLs, inlined
  SVG for a chart, data URI for a local image, remote image URL kept;
  palette contract over three themes; settings clamp for `sepia` and
  `BodyFont`.
- Manual (user): Quick Look on a few documents; paste a screenshot; open an
  exported HTML file in Safari and another browser, offline; sepia and each
  font in the preview and PDF.
