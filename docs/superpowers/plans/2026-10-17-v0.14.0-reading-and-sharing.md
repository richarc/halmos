# v0.14.0 Reading and Sharing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Task lists and alerts, a code copy button, image paste, self-contained HTML export, a sepia theme with a body-font choice, and a Quick Look preview extension.

**Architecture:** Rendering additions go into the shared markdown-it setup (`lib/markdownParser.ts`) so the preview and the citation recogniser stay in step. Image paste and HTML export each add a small Go binding pair (choose/write) with the frontend doing the assembly. Sepia and body font are two `Settings` fields driving attributes/variables on the preview. Quick Look is a separate Swift `.appex` hosting a `WKWebView` that loads a preview-only page built from the same frontend; it starts with a go/no-go spike and can be dropped from the release.

**Tech Stack:** Go + Wails v3 beta.12, Svelte 5 + TS, CodeMirror 6, markdown-it, `@mdit/plugin-tasklist`, `@mdit/plugin-alert`, Swift (QuickLookUI, WebKit) for the extension.

**Spec:** `docs/superpowers/specs/2026-10-17-v0.14.0-reading-and-sharing-design.md`

## Global Constraints

- Work on branch `v0.14.0-reading-sharing`. Version strings stay 0.13.0 (bumped at release).
- Bindings regenerated with `wails3 task common:generate:bindings`, never hand-edited.
- Settings only through the `Settings` struct (`settings.go`): field + json tag + default + clamp in `normalise`.
- Colours only as palette tokens; `styleContract.test.ts` stays green; `--doc-*` tokens never appear in a theme block.
- Menu accelerators in `menu.go`; check `defaultKeymap`/`foldKeymap` before binding.
- No new network access. Exported HTML loads nothing remote except images the document already references remotely, and contains no `<script>`.
- Render path: nothing new runs per keystroke beyond what the preview render already does.
- Exact copy: "Save the document before pasting images"; menu items "Export HTML…", View → "Body Font", Appearance item "Sepia"; copy button labels "Copy" / "Copied".
- Body fonts (label → CSS value): New York → `ui-serif, 'New York', Georgia, serif` (default, today's value); Charter → `Charter, Georgia, serif`; Iowan Old Style → `'Iowan Old Style', Georgia, serif`; Palatino → `Palatino, 'Palatino Linotype', serif`; Georgia → `Georgia, serif`; System Sans → `-apple-system, 'Helvetica Neue', sans-serif`. Setting values: `new-york`, `charter`, `iowan`, `palatino`, `georgia`, `system-sans`.
- Pasted image names: `pasted-YYYYMMDD-HHMMSS.<ext>` in `images/` beside the document, `-2`, `-3`… on collision, never overwrite.
- Verification: `go test ./. && go build -o /dev/null .`; `npm --prefix frontend test`; `npm --prefix frontend run check`.

## Review Focus

1. Pasting an image twice within the same second: second file gets `-2`, first is untouched (Task 3 test).
2. HTML export of a document with an unsaved/untitled path, a missing local image, and a remote image: export still succeeds, missing image keeps a visible broken `<img>` with its original src, remote URL kept (Task 5 test).
3. An alert or task list inside a blockquote/list nesting, and `[!NOTE]` written in lower case: renders like GitHub (Task 1 test).
4. Switching theme to sepia then printing/exporting: PDF and HTML are white paper (Task 4 test on print CSS / export stylesheet).
5. Copy button on a code block whose text contains HTML-like content (`<script>`): copied text is the literal source, button never injects markup (Task 2 test).
