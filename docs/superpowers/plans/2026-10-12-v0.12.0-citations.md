# v0.12.0 Seamless Citations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make citing in Hermes seamless: autocomplete, hover preview, unknown-key warnings, a style picker, clear Zotero errors, and footnotes.

**Architecture:** One shared key recogniser (`lib/citationKeys.ts`) agrees with the preview's markdown-it rule and feeds every editor feature. App owns the loaded bibliography and hands the editor a read-only `CitationContext` through a getter prop; the editor refreshes its decorations when App tells it the bibliography changed. Go gains small bindings for the style file, the style menu and Zotero status.

**Tech Stack:** Go + Wails v3 beta.12, Svelte 5, CodeMirror 6 (`@codemirror/autocomplete`, `hoverTooltip`), markdown-it + `markdown-it-footnote`, citeproc-js.

**Spec:** `docs/superpowers/specs/2026-10-12-v0.12.0-citations-design.md`

## Global Constraints

- Work on a branch `v0.12.0-citations`; version strings stay 0.11.4 (bumped at release, not in this plan).
- Bindings are regenerated with `wails3 task common:generate:bindings`, never hand-edited.
- Menu accelerators live in `menu.go`; check `defaultKeymap`, `foldKeymap` and the autocomplete keymap before binding any chord.
- Colours only as palette tokens in `frontend/public/style.css`; `styleContract.test.ts` must stay green. The editor's unknown-key underline uses the existing `--cite-error-fg`.
- No network beyond `127.0.0.1:23119`.
- Typing path: no full-document scan per keystroke. Full scans are debounced (reuse `lib/debounce.ts`).
- Verification commands: `go test ./. && go build -o /dev/null .`; `npm --prefix frontend test`; `npm --prefix frontend run check` (svelte-check).
- Copy fixed by the spec, verbatim: "Zotero isn't running. Open Zotero, then try again." and "Zotero is running but the Better BibTeX plugin isn't installed. Hermes uses it to pick citations and to export your library as a .bib file."
- Order at document end: References, then Footnotes.

## Review Focus

1. A large `.bib` (5,000 entries): autocomplete must stay responsive — options capped at 100 (Task 3 test).
2. A document with no `bibliography:` key: no underlines, no status count, no popup (Tasks 3, 5, 6 tests).
3. A key followed by sentence punctuation (`@smith2020.` / `@smith2020:`): the recognised range excludes the punctuation, matching `parseKey` (Task 1 test).
4. Frontmatter variants when writing `csl:` — none, empty block, CRLF, quoted existing value (Task 7 test).
5. The `.bib` changes on disk (`bib:changed`) while the document is open: underlines and status count update without a keystroke (Task 5 test via `refreshCitations`).

it('spans exclude trailing sentence punctuation', () => {

- [ ] **Step 3: Implement** in `citationKeys.ts`. Approach: parse with a markdown-it instance using `citationPlugin` (as `citationFeedback.ts` does) so agreement is structural, then locate each emitted token's raw text (`token.content`) in the source by walking inline tokens with the block token's `map` line range, and find each key inside the raw text with `KEY_RE` plus the same trailing-punctuation trim as `parseKey`. Frontmatter is stripped with `parseFrontmatter` and offsets shifted back. If the walk proves unreliable, the fallback is a scanner reproducing `bracketRule`/`narrativeRule` — either way the corpus test is the arbiter.
