# pre1.0-cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix every finding of the 2026-10-30 architecture review (and finding 21, added 2026-10-31) before the 1.0 freeze: six small defects, the Wails v3.0.0 patterns the app does not yet use, and the structural splits that get harder after 1.0.

**Architecture:** Three parts, in order. Part A (Tasks 1–6 and 21) fixes defects in place. Part B (Tasks 7–14) adopts typed events, an atomic settings update, typed file errors and the v3.0.0 build template. Part C (Tasks 15–20) moves code: settings and update check into their own services, Wails-free code into `internal/` packages, `App.svelte`'s event wiring into a module, and non-macOS stubs. Each task is one commit series on branch `pre1.0-cleanup` and leaves both test suites green.

**Tech Stack:** Go 1.26 (toolchain go1.26.10), Wails v3.0.0, cgo/Objective-C on darwin, Svelte 5 + TypeScript, vitest, Task.

**Spec:** `docs/superpowers/specs/2026-10-30-pre1.0-cleanup-design.md` (finding numbers below are the spec's).

## Global Constraints

- Wails stays at exactly `v3.0.0` (go.mod, `wails3` CLI, `@wailsio/runtime`); KaTeX `0.19.1`, Mermaid `12.2.0`.
- Never run `wails3 task common:update:build-assets`; port template changes by hand.
- Bundle id `com.qxquantum.hermes`, data dir `hermes/`, module `hermes`, `/_hermes/image`, `HERMES_DEMO` keep their names.
- Every task ends with `go test ./.`, `go test -tags nopaid ./.`, `go vet ./.` and, when the frontend changed, `cd frontend && npx vitest run < /dev/null` and `npx svelte-check --threshold error`, all green.
- After changing a service's API, regenerate bindings with `wails3 task common:generate:bindings`; never hand-edit `frontend/bindings/`.
- Before saying a change works in the app, build (`wails3 task build`) and confirm the binary contains it with `strings "bin/Halmos Editor" | grep <new symbol>`.
- No user-visible change except the bugs fixed. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Manual app checks are the user's (no GUI tool): list them in the task's report, don't claim them.

## Review Focus

1. A palette command or menu item that changes a setting while the frontend writes another (Outline toggle during the update question): both changes must survive. Task 7 pins it with `TestChangeSettingsKeepsConcurrentField`.
2. A registered event emitted with the wrong payload type is cancelled at runtime by Wails, so a missed call site silently stops a feature. Task 10 pins every emitted name and payload with `TestEveryEmittedEventIsRegistered`.
3. Saving a document reached through a symlink in a folder the user cannot write (link in a writable folder, target elsewhere): the save must fail with a permission code, not replace the link. Task 9 `TestSaveThroughSymlinkToReadOnlyTarget`.
4. A `bibliography:` value with upper-case extension (`Refs.BIB`) must still load. Task 4 `TestReadBibliographyAcceptsUpperCaseExtension`.
5. Print or Export PDF run from the command palette while the palette's own panel is still closing: must print the document in the chosen orientation (manual check in Task 5).
