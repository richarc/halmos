# Third-party licence notices Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every copy of Halmos Editor carries the copyright and licence text of everything it bundles, in `Contents/Resources/licences/THIRD-PARTY-NOTICES.txt` and at Help → Acknowledgements.

**Architecture:** A Vite plugin written in this repository collects the npm packages Rollup actually bundled (app build plus its Web Worker build), reads each one's own licence file (or a version-keyed override kept in `licenses/overrides/`), adds the Go modules from `go list -deps` and the Go standard library, and writes `acknowledgements.json` and `THIRD-PARTY-NOTICES.txt` into `frontend/dist`. The Quick Look build runs the same plugin in check mode against that JSON. `bundle:licences:copy` copies the text file into the bundle; `release` checks it is there and covers the shipped binary's Go modules. The page reads the JSON as a static asset when opened.

**Tech Stack:** TypeScript (Node, Vite 7 plugin API, vitest 4), Go 1.26, Wails v3.0.0, Svelte 5, Task.

**Spec:** `docs/superpowers/specs/2026-11-01-third-party-notices-design.md`

**Precondition:** branch from `main` **after** `pre1.0-cleanup` is merged. Tasks 5 and 6 use `events.go`, `subscribeAppEvents` (`frontend/src/lib/appEvents.ts`) and `release:check-tree`, which exist only on that branch today.

## Global Constraints

- No new npm or Go dependency (dependency hold from 2026-10-29; spec: "No new npm dependency for this").
- Licence text comes from the component's own licence file, never from a template filled in from the licence name.
- A package with no licence file and no override for its exact `name@version` fails the build. An override for a package that ships with its own licence file, or that no longer ships, also fails the build.
- Elections, verbatim in the output: citeproc-js — "Halmos elects the CPAL-1.0 option."; DOMPurify — "Halmos elects the Apache-2.0 option."
- citeproc-js and elkjs entries each carry the full licence text (CPAL-1.0, EPL-2.0) and a source statement: "Source code for this version: <repository URL>, version <version>."
- Bundle path: `Contents/Resources/licences/THIRD-PARTY-NOTICES.txt`, in both `package` and `release`.
- Generated files never go in `build/Taskfile.yml` or `build/darwin/Taskfile.yml` (regenerated by `update:build-assets`); Taskfile changes go in the root `Taskfile.yml`.
- The notices data is loaded only when the Acknowledgements page opens, never at startup.
- Colours only through `style.css` tokens (`styleContract.test.ts`).
- Test commands: `go test ./. ./internal/...`, `go test -tags nopaid ./. ./internal/...`, `cd frontend && npx vitest run < /dev/null`, `cd frontend && npx svelte-check`.
- Voice for user-facing text and docs: plain English, no hype.

## Review Focus

1. A package bundled at two versions (nested `node_modules`) — expect two entries, one per version, each with its own licence text.
2. A scoped package path (`node_modules/@scope/name/...`) and a nested one (`node_modules/a/node_modules/b/...`) — expect `@scope/name` and `b` respectively, never `a`.
3. Virtual and query-suffixed module ids (`\0vite/...`, `...?worker`, `...?inline`) — expect them skipped or stripped, not a crash or a bogus package.
4. The worker's packages (`@retorquere/bibtex-parser` and its `@unified-latex/*`) — expect them in the output, proving the worker pass is collected.
5. A licence file named in an unusual way (`license`, `LICENCE.md`, `COPYING`, `LICENSE-MIT`) — expect it found.

Each line has its test in Task 2 or Task 3.

### Task 2: The notices generator (pure functions)

**Files:**
- Create: `frontend/scripts/notices/notices.ts`
- Test: `frontend/scripts/notices/notices.test.ts`, fixtures under `frontend/scripts/notices/fixtures/` (a fake `node_modules` tree and an `overrides/` dir)
- Modify: `frontend/vitest.config.ts` only if `scripts/**` is not already picked up (vitest's default include covers it)

**Interfaces:**
- Produces:
  - `type NoticeEntry = { name: string; version: string; licence: string; copyright: string[]; text: string; election?: string; source?: string; extraText?: string; origin: 'npm' | 'go' }`
  - `type Notices = { generatedBy: 'halmos-notices'; entries: NoticeEntry[] }` (entries sorted by `name`, then `version`)
  - `packageOf(moduleId: string): { name: string; dir: string } | null`
  - `overrideFileName(name: string, version: string): string`
  - `npmEntry(dir: string, overridesDir: string): NoticeEntry` — throws `Error` naming the package when no licence file and no override exist
  - `goEntries(modules: { path: string; version: string; dir: string }[], goroot: string, goVersion: string): NoticeEntry[]` — one entry per module plus `{ name: 'Go standard library and runtime', version: goVersion, ... }` from `<goroot>/LICENSE`
  - `checkOverrides(used: Set<string>, overridesDir: string, ownFile: Set<string>): void` — throws on an override file not in `used`, or for a package that has its own licence file (`ownFile`)
  - `applyElections(e: NoticeEntry, licencesDir: string): NoticeEntry` — citeproc → election + CPAL `extraText` + source; elkjs → EPL `extraText` + source; dompurify → election. Source URL from the package's `repository` field.
  - `renderText(n: Notices): string`
  - `missingFrom(n: Notices, ids: { name: string; version: string }[]): string[]` (for check mode)
