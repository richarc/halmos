# v0.11.4 — Open Issues (#17, #18, #19) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.11.4 fixing the three open GitHub issues: the app stays running after its window closes (#17), Find is reachable from the menu (#18), and Hermes registers as an editor for `.md` files and opens files handed to it by Finder (#19).

**Architecture:** #17 stops the window from being destroyed: the close hook always cancels, and a clean close hides the window and tells the frontend to reset to the welcome screen; Wails' built-in `ApplicationShouldHandleReopen` handler already re-shows hidden windows on a Dock click. #18 adds an explicit Find submenu to the Edit menu that routes through a new `menu:find` event to `@codemirror/search` commands, because the native `Find` roles send `performTextFinderAction:` to WKWebView, which searches rendered page text, not CodeMirror's virtualised document. #19 declares `fileAssociations` in `build/config.yml` (mirrored into both Info plists) and handles `events.Common.ApplicationOpenedWithFile`, buffering a path that arrives before the frontend is listening.

**Tech Stack:** Go + Wails v3.0.0-beta.12, Svelte 5, CodeMirror 6 (`@codemirror/search` 6.7.x, already installed transitively), vitest.

**Spec:** GitHub issues #17, #18, #19 (`gh issue view <n>`). No separate design doc.

## Global Constraints

- Version: `0.11.4` in `build/config.yml` and `updates/latest.json`, bumped together (README release steps: bump, publish, push last).
- Wails pin unchanged: `v3.0.0-beta.12`.
- Do **not** run `wails3 task common:update:build-assets` — it overwrites hand edits (`build/darwin/Taskfile.yml` `run` deps, icon keys; see `app-icon` skill). Hand-edit both plists to match what the template would emit from `config.yml`.
- Event payloads are untyped; type them at the `Events.On` call site.
- No new accelerator may collide with an existing one: ⌘E is Export PDF, so no "Use Selection for Find".
- Colours only via existing CSS variables (`styleContract.test.ts`).
- Verification: `go test ./. && go build -o /dev/null .` and `cd frontend && npm test`. Before claiming anything works in the app, `wails3 task package` and confirm the binary is fresh.
- GUI behaviour (Dock, Finder Open With, menus) needs a user click-through at the end — agents cannot drive the native window.

## Review Focus

- Closing a **dirty** document via the red button: must raise the save/discard dialog, and after Save or Discard the window hides (does not quit). Cancel leaves the window open. → Task 1 test `close:confirm with "close" payload hides after discard`.
- ⌘Q while the window is hidden: quits immediately, no dialog, no hang. → covered by unchanged `quitRequest` (doc is clean once hidden); Task 1 test asserts the hidden state is clean.
- File opened from Finder while the **current document is dirty**: must go through the existing unsaved-changes dialog, not overwrite. → Task 3 test `file:open while dirty raises the pending-open dialog`.
- Cold launch by double-clicking a `.md`: the file opens instead of the welcome pane / first-launch template. → Task 3 Go test for `launchFiles` ordering and frontend test for `TakeLaunchFile`.
- ⌘F while the welcome screen or a builder modal is up: no-op, does not edit the hidden document. → Task 2 test `menu:find is ignored on the welcome screen`.
